# 取材勉強会・文字起こし教材化 Skill

## Skillの目的

新聞社内の勉強会・取材ノウハウ共有・講評・質疑応答の文字起こしを、若手記者や他部署の記者が学べる社内教材へ変換する。

単なる要約ではなく、実例から「見方・聞き方・確かめ方」を抽出し、図解スライド・PDF・将来的な動画化のたたき台まで展開できる再現型ワークフロー。

---

## 中核方針

| 禁止 | 代わりにすること |
|---|---|
| 文字起こしをそのまま貼る | 事実・実例・メソッド・判断軸に分解する |
| チェックリストで終わる | メソッド・判断軸・視点の3軸で構成する |
| 抽象論・精神論で終わる | 実例カード・対比図・場面分解で具体化する |
| 原文にない断定 | 「原文を超えた断定がないか」をファクトチェックで確認する |
| 情報源が特定される表現をそのまま掲載 | 公開範囲に応じて抽象化する |
| 人名・肩書・日付・数字の未確認 | 必ずファクトチェック欄に記録する |
| 「原文」「内部処理」「文字起こし上」などの言葉を完成スライドに出す | 読者向け表現（「勉強会で出た」など）に置き換える |
| 1画像に複数スライドを詰め込む | 1画像ファイル＝1スライドを徹底する |
| PDFリンクをクリック不可な形式で提示 | sandboxリンク形式で提示する |

---

## 標準ワークフロー（7段階）

```
[1] 入力確認
 └→ [2] 文字起こし分解
      └→ [3] 教材コンセプト化（3語の柱）
           └→ [4] スライド台本作成（文字ベース）
                └→ [5] ファクトチェック
                     └→ [6] 図解スライド生成（1枚1ファイル）
                          └→ [7] PDF化・改善ログ
```

各工程のプロンプトは `prompts/` ディレクトリに分割して格納。

---

## 各段階の処理内容

### 1. 入力確認

以下を必ず確認する。未入力の項目はユーザーに問い返す。

- 文字起こし本文
- 発言者名・肩書
- 日時・場所
- 勉強会の目的
- 想定読者（若手記者／他部署／外部研修など）
- 公開範囲（社内限定／部署内／外部公開可）
- 出力形式（スライド台本のみ／画像生成まで／PDF化まで）

### 2. 文字起こし分解

文字起こしを以下8カテゴリに仕分ける。

| カテゴリ | 内容 |
|---|---|
| 事実 | 発言として確認できる客観的な情報 |
| 実例 | 具体的な取材エピソード・事例 |
| 発言者のノウハウ | 個人の経験知・判断基準 |
| 若手向けメソッド | 汎用化できる手法・アプローチ |
| 判断軸 | 「こういう場面ではこう考える」という軸 |
| 注意点 | 誤解しやすい点・罠になりやすい点 |
| 引用候補 | そのまま引用に使えそうな発言 |
| 要確認事項 | 人名・数字・因果関係など確認が必要なもの |

### 3. 教材コンセプト化

教材全体を**3語程度の柱**で整理し、スライド全体の骨格とする。

例：
- 観察・違和感・検証
- 準備・質問・裏取り
- 制度・数字・影響
- 根拠・表現・リスク

### 4. スライド台本作成

画像生成の前に、必ず文字ベースで台本を作る。各スライドに以下を入れる。

```
スライド番号：
タイトル：
ここがポイント（1行）：
本文（3〜5行）：
実例カード：
図解形式：
注意ボックス：
ファクト確認欄：
```

### 5. ファクトチェック

台本完成後、以下を必ず確認する。

- 人名表記（姓のみ／フルネームの統一）
- 肩書の正確性
- 日付・数字
- 固有名詞
- 引用の正確性
- 因果関係（原文にない断定がないか）
- 内部処理語がスライド本文に出ていないか

### 6. 図解スライド生成

GPT Image 2.0等で画像生成する場合のルール。

- 1画像ファイル＝1スライド（厳守）
- 1枚1メッセージ
- 内容は変えず視覚設計だけ改善する場合はその旨を明記
- 実例は本文に埋めず、実例カード化する
- 注意点は注意ボックスに分ける
- 比較できる内容は表・対比図で整理する
- アイコンは意味があるものだけ使う

### 7. PDF化・改善ログ

- スライド順を確認
- 画像ファイル名を連番化（例：slide_01.png）
- 1枚ずつPDFページ化
- 1セットのPDFに統合
- sandboxリンク形式でクリック可能なリンクを提示
- 運用中に発生した問題を `improvement_log.md` に記録

---

## 視覚設計ルール

| 色 | 用途 |
|---|---|
| 濃紺 | 見出し・結論 |
| 黄色 | 重要キーワード |
| 緑 | 実践メソッド・前向きな学び |
| 赤 | 注意点・誤解しやすい点 |
| グレー | 補足情報 |

### デザイン原則

- 新聞社の社内研修資料として自然な見た目
- PowerPointで人が丁寧に作ったような資料
- 余白を多めに取る
- 1枚1メッセージ（複数のメッセージを1枚に詰め込まない）
- AI画像っぽい派手な装飾・過剰なグラデーション禁止
- 意味の薄いアイコン禁止

| 06 | メソッド3 | 関係構築と継続的な会話 |

| 08 | メソッド5 | 裏取りの段階と方法 |
| 09 | メソッド6 | 掲載後対応と関係の持続 |
| 10 | まとめ | 判断軸と持ち帰る視点 |
